# ADR-0004：独立服务、多空间与管理页面

## 状态

方向已接受，实施待完成。日期：2026-10-09；基线：4.6.30。

## 背景

当前 MCP 实例启动时绑定一个 workspace，HTTP 主要提供 JSON API，交互式展示交给 DSH。已有全局 registry 和 group，但用户希望一次安装独立服务，通过管理页面接入不同项目，并逐步承载文档知识库、Wiki 与长期记忆。

## 决策

1. Memory Center 新增本机常驻服务和独立管理页面；MCP 是 AI 能力入口，管理 API 是项目登记、授权与运维入口。DSH 继续作为客户端。
2. 首版界面的项目对应现有 workspace。一个服务登记多个 workspace，各自拥有配置、索引与工程记忆；现有 `project` 服务分区参数不改变含义。
3. 请求使用经过授权的稳定 `workspace_id` 与不可变上下文；session、task、ref、缓存和审计均按空间隔离，不在共享实例上切换可变当前空间。
4. 服务控制面可使用独立 SQLite catalog；空间 graph.db 继续保存既有运行时事实。联合查询为授权结果聚合，不混写所有代码图或记忆。
5. 既有 workspace 优先按 external 模式登记引用，不自动搬迁。managed 数据目录和旧 registry 导入必须通过兼容验证。
6. 复用应用用例、索引协调器与任务账本，不在管理页面或服务层复制工程事实和状态机。
7. 旧单空间 CLI/MCP/HTTP 合同继续有效；新传输与可选路由参数采用兼容演进。第一阶段本机单用户，团队远程服务另行立项。

## 与既有决策的关系

- ADR-0001 和 ADR-0002 的核心依赖方向继续有效。
- ADR-0003 的旧图构建器下线继续有效；独立管理页面不等于恢复旧图展示实现。
- `HTTP_DISPLAY_MIGRATION.md` 继续描述 4.6.30 的事实。本决策替代“未来展示只能由 DSH 承担”的产品约束，尚未改变旧路由的运行行为。
- `NEXT_PHASE_MASTER_PLAN.md` 仍是唯一开发路线入口；服务化切片优先级由其分支附录明确。

## 后果与失效条件

新增生命周期、认证、请求路由、打包和跨空间并发测试的维护责任。服务部署位置与源码位置分离，远程服务须具备明确采集合同，不能依赖客户端本地路径。

若单进程/本机单用户模型无法满足已验证的负载或团队需求，另立 ADR 调整进程、授权和存储模型；不在首版预先引入多实例或集中式全量代码图。

具体技术设计和验收见 [服务化技术方案](../SERVICE_PLATFORM_TECHNICAL_PLAN.md)。
