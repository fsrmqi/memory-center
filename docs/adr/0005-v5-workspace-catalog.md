# ADR-0005：5.0 项目目录与登记配置

## 状态

已实施，适用 5.0.0b32。延续 ADR-0001 与 ADR-0004。

## 决策

1. 服务级 `catalog.db` 独立承载项目身份、登记状态、源码根目录与服务划分。应用层通过 `CatalogStore` 访问；不读写旧全局 registry。
2. 登记配置唯一权威来源为 catalog。后续如果引擎需要 workspace.yaml，按 catalog 派生，不建立第二条可独立修改的登记路径。每个 workspace 的索引/记忆事实仍进入独立事实库。
3. 项目 ID 随机生成，服务 ID 基于项目 ID 和相对路径生成。名称和源码位置不充当身份；名称/路径改变保留项目 ID，相同服务相对路径保留服务 ID。
4. 源码只读、有界预览；登记时重新识别，并在一个 SQLite 写事务内检查根目录重叠、名称冲突、写入项目和服务配置。失败回滚，无文件系统半登记状态。
5. 配置目录按使用需求惰性创建：登记只写 catalog 与管理员令牌，项目索引/任务目录在使用时创建，不能因为登记而自动索引。
6. 更新使用 revision 比较，拒绝丢失更新；移动源码前先暂停。移除接入保留数据与记录，不复用原 ID；重新登记生成新身份。
7. 管理 API 使用独立的本机管理员令牌，文件权限 0600，并校验 Host/Origin/JSON。令牌不进入 MCP 输出；普通 MCP 凭据与空间授权不能借此获得管理权限。

## 后果与后续约束

- root/子服务排除路径属于新配置合同，构造引擎输入时必须遵守，不能重复扫描父子服务。
- `active` 只表示允许接入，不代表索引已建；新登记项目初始为 not_indexed。
- 暂停/移除后对已有任务、session、凭据的处理需在恢复前人工确认，不自动清理。
- 单服务进程和 SQLite 事务是本机部署边界，多实例与团队部署需要重新定义租约和存储，不默认支持。
- catalog schema 或管理员令牌无效时拒绝启动，不覆盖旧库，不静默换令牌。
- 没有 4.x 数据导入、外部 workspace 模式或旧接口兼容转发。

运行合同见 [项目目录指南](../V5_CATALOG_GUIDE.md)；实现过程与验证记录属内部资料，不随公开仓库发布。
