# 5.0 S1 项目目录实施回执

> 类型：历史验证证据（historical）。日期：2026-10-09。版本：5.0.0a2，开发预览，未正式发布。
> 分支：`codex/service-platform`。S1 已完成；S2 等待用户确认，未开始。

## 实际交付

- 新增服务级 SQLite `CatalogStore`，schema version 1，WAL，每次操作独立连接，读快照/写事务，配置与服务划分原子提交。
- 新增 `WorkspaceCatalog` 应用用例，稳定 workspace ID、按相对路径确定 service ID、revision 并发控制、config_version 和登记状态。
- 新增有界源码预览：复用服务类型注册表，识别根目录及两层子目录，最多 2048 个目录项/64 个服务，JVM 标记读取上限 16 KiB；排除生成目录、依赖和子目录软链接。
- 新增受管理员令牌保护的预览、登记、列表、详情、改名、暂停、路径调整、恢复和移除 API。没有令牌、无效 Host/Origin、非 JSON 写入均被拒绝。
- 源码根目录规范化，拒绝同名、重复实际路径和父子目录重叠；移动路径前先暂停，同一服务相对路径不变时保留 ID。
- 移除仅取消接入并保留数据，重新登记分配新身份。登记配置只存 catalog，不再写第二份 YAML 真源。
- catalog、管理员令牌文件权限 0600；未知 catalog schema、软链接数据库、非法/特殊令牌文件阻止就绪，不静默覆盖。
- 新增 Compose 源码只读挂载配置，状态页明确显示 S1/5.0.0a2 与当前管理 API 边界。

本阶段不会初始化索引或创建 Worker；项目始终返回 not_indexed。项目查询/MCP 凭据隔离留到 S2，任务排空留到 S3，完整交互页面留到 S4。

源码和旧 workspace/registry 未改动。5.0 服务入口不导入旧登记路径；旧入口源码暂留，按后续切片替换/移除，不提供兼容转发。

Memory Center 宿主绑定另一工程，mc_analyze 对当前仓库文件错误锚定到其他工程；该结果未用作修改证据，未据此扩展修改或刷新那个工程的索引。
