# 5.0.0b3 多 Wiki 目录接入回执

日期：2026-10-10。

## 已实现范围

- 管理页新增“Wiki 目录”：独立登记多个绝对目录，关联多个项目，支持自动同步开关、暂停、配置和移除。
- 递归读取 UTF-8 Markdown，保留目录来源与相对路径。正文原文件为真源，数据库保存可重建的派生快照；原目录始终只读。
- 完整扫描后在单事务内更新新增、修改及删除页面；稳定页面身份、未变页面修订不变。目录失效、编码或预算失败保留上次完整结果，不发布部分快照。
- 手动同步后提交关联项目索引；约每分钟自动检查，持久快照标识补偿同步与索引重叠。索引仍复用完整项目 generation 发布流程，不声称仅重建变化块的向量。
- 项目 Wiki 列表、关键词 / 向量检索和引用复用现有链路；目录文件变化标记 STALE 并拒绝旧引用。API/MCP 禁止修改目录派生页面。暂停、移除及解除关联立即退出对应项目召回。
- 新增 `compose.wikis.yaml` 只读挂载，支持同父目录的多个 Wiki；分散目录可在私有 override 增加挂载。MCP 工具 schema 未改变。

## 验证证据

- 完整服务、架构边界和文档契约回归：75 项通过，含 PostgreSQL/pgvector；两项依赖弃用警告。
- 专项覆盖多目录同名文件、跨项目共享与隔离、稳定修订、删除及恢复、目录失效、UTF-8 失败、超预算、符号链接排除、只读 HTTP/MCP、过期引用、自动同步与暂停召回。
- Ruff、Vue 类型检查、Vite、wheel/sdist 和 Docker 镜像构建通过；Compose Wiki overlay 配置校验通过。
- 实际容器用两个只读 Wiki bind 挂载同步成功，关联项目读到两页；主运行服务升级至 5.0.0b3 并就绪。
- 浏览器在隔离验收实例完成两目录登记、项目关联、立即同步、计数显示及项目 Wiki 只读列表检查。无相关控制台错误；主服务刷新后显示新入口。验收数据未写入用户运行服务。
- GitNexus 已刷新索引；提交前使用完整结构化 scope=all 审查，结果无 partial/truncated/error。风险为 CRITICAL，知识入口、后台索引与来源引用需作为整体验证，不将空调用集解释为无影响。

## 使用边界

每目录最多 2000 页 / 32 MiB，单页 1 MiB；最多登记 100 个来源。当前读取 Markdown 正文，不导入附件或解析 Wiki 专有链接。目录回写未开放，原文件须单独备份。大规模目录性能与真实模型语义评测未在本轮完成。

操作及容器挂载说明见 [平台指南](../V5_PLATFORM_GUIDE.md)。
