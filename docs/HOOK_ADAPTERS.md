# Hook Adapters Guide / Hook 适配器指南

## Overview / 概述

Hook adapters translate the declarative `hooks.yaml` specification into host-specific configuration formats. Each adapter reads hooks.yaml and generates the appropriate config for its host platform.

Hook 适配器将声明式 `hooks.yaml` 规范翻译为宿主特定配置格式。每个适配器读取 hooks.yaml 并生成对应宿主平台的配置。

Currently implemented adapters:
当前已实现的适配器：

- **Claude Code** (full implementation)
- **Codex** (placeholder)
- **Cursor** (placeholder)

## Claude Code Adapter / Claude Code 适配器

### Usage / 使用

```bash
memory-center generate-hooks --workspace <workspace.yaml> --host claude-code
```

This reads hooks.yaml from the workspace, generates Claude Code `settings.local.json` hooks section, and writes it to `.claude/settings.local.json` relative to the workspace root. Existing settings (permissions, env, etc.) are preserved — only the `hooks` key is replaced.

从 workspace hooks.yaml 读取，生成 Claude Code `settings.local.json` 的 hooks 部分，写到 workspace root 的 `.claude/settings.local.json`。已有设置（permissions, env 等）会保留，只替换 `hooks` 键。

### Event Mapping / 事件映射

| hooks.yaml event | Claude Code hook | matcher |
|------------------|------------------|---------|
| `session_start` | `SessionStart` | `""` |
| `pre_edit` | `PreToolUse` | from `filter.tool_matcher` |
| `session_stop` | `Stop` | `""` |
| `user_prompt_submit` | Not generated by default | — |

### Mode Translation / 模式翻译

| hooks.yaml mode | Claude Code hook type | Command |
|------------------|----------------------|---------|
| `soft` | `type: "command"` | `memory-center run-hook --workspace <path> --hook <event>` |
| `guard` | `type: "command"` | `memory-center run-hook --workspace <path> --hook <event>` (exit 2 blocks tool call) |
| `suggest` | Not generated by default in Claude Code | Claude/Codex 中默认跳过，避免打断普通自然语言请求 |
| `off` | Not generated | Skipped |

### Key Improvement / 关键改进

The adapter replaces the current **fragile inline shell commands** with a single clean `memory-center run-hook` call. The runner handles parameter resolution, mode enforcement, and facade dispatch internally — no inline Python/shell parsing needed.

适配器将当前**脆弱的 inline shell 命令**替换为单一的 `memory-center run-hook` 调用。Runner 内部处理参数解析、模式执行和 facade 调度，不再需要 inline Python/shell 解析。

### Why `UserPromptSubmit` is skipped by default / 为什么默认跳过 `UserPromptSubmit`

Claude Code 和 Codex 这类宿主会把 prompt 型 hook 当成用户输入链路的一部分处理。对于 `同步下文档`、`继续`、`下一步` 这类普通自然语言操作，建议型 prompt 很容易被宿主解释成一次需要先完成的判断步骤，进而造成“Operation stopped by hook”一类打断体验。

因此当前实现选择：

- `session_start / pre_edit / session_stop` 继续生成
- `user_prompt_submit` 在 Claude Code / Codex 适配器中默认不生成
- 如确有需要，应在特定宿主上手工启用，而不是作为默认行为

### Guard Mode Blocking / guard 模式阻塞

When `pre_edit` runs in `guard` mode and finds must-severity rules matching the target file, `run-hook` returns exit code 2. Claude Code interprets exit code 2 from PreToolUse hooks as "block the tool call" — the Edit/Write is prevented.

当 `pre_edit` 在 `guard` 模式下运行且发现 must-severity 规则匹配目标文件时，`run-hook` 返回 exit code 2。Claude Code 将 PreToolUse hook 的 exit code 2 解释为"阻塞工具调用"——Edit/Write 被阻止。

## Codex Adapter / Codex 适配器

### Usage / 使用

```bash
memory-center generate-hooks --workspace <workspace.yaml> --host codex
```

Generates shell wrapper scripts in `.codex-hooks/` directory relative to workspace root. Each script calls `memory-center run-hook`.

在 workspace root 的 `.codex-hooks/` 目录下生成 shell wrapper scripts。每个脚本调用 `memory-center run-hook`。

**Note**: Codex's hook API is still evolving. This adapter is a minimal placeholder.

**注意**：Codex 的 hook API 还在演进中。此适配器是最小 placeholder。

## Cursor Adapter / Cursor 适配器

### Usage / 使用

```bash
memory-center generate-hooks --workspace <workspace.yaml> --host cursor
```

Generates `.cursorrules` additions referencing Memory Center's recommended workflow.

生成 `.cursorrules` 补充内容，引用 Memory Center 推荐工作流。

**Note**: Cursor uses `.cursorrules` and task-level hooks. This adapter is a minimal placeholder.

**注意**：Cursor 使用 `.cursorrules` 和任务级 hooks。此适配器是最小 placeholder。

## Adding New Adapters / 添加新适配器

To add a new host adapter:

添加新宿主适配器：

1. Create `memory_center/hooks/adapters/<host_name>.py`
2. Implement a `generate_<host_name>_hooks(workspace, hooks_config, ...)` function
3. Map hooks.yaml events to the host's lifecycle hook names
4. Translate modes to the host's hook type/format
5. Add the host to `generate-hooks_cmd` in `memory_center/cli/main.py`
6. Add tests in `tests/test_hooks_adapters.py`

1. 创建 `memory_center/hooks/adapters/<host_name>.py`
2. 实现 `generate_<host_name>_hooks(workspace, hooks_config, ...)` 函数
3. 将 hooks.yaml 事件映射到宿主生命周期 hook 名称
4. 将模式翻译到宿主的 hook 类型/格式
5. 在 `memory_center/cli/main.py` 的 `generate-hooks_cmd` 中添加宿主
6. 在 `tests/test_hooks_adapters.py` 中添加测试
